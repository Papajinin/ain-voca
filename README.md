# AIN 영단어 — 관리 안내서

Oxford 5000 기반 영어 단어 학습 웹앱입니다. GitHub Pages로 배포하고, 아이폰 Safari에서 "홈 화면에 추가"해 앱처럼 사용합니다.

화면은 `index.html` **한 페이지 안에서** 전환됩니다(페이지 이동 없음). 디자인, 단어 데이터, 기능 코드만 역할별 파일로 나뉘어 있습니다.

---

## 1. 파일 구성

모든 파일은 저장소 **맨 위(루트)** 에 둡니다. 하위 폴더는 쓰지 않습니다.

| `style.css` | 학교 테마 4종 색상(헤더 로고·시작 화면 색 포함), 글꼴, 애니메이션 |

| `category.js` | ① 카테고리 화면 (레벨, 품사 그룹 카드) |

| `days.js` | ③ 학습단계 화면 (Stage 목록, 진도율, 영한/한영 선택) |

## 2. 무엇을 바꾸려면 어느 파일을 고치나

| 하고 싶은 일 | 고칠 파일 |
|---|---|
| 화면에 보이는 고정 문구, 버튼 배치, 여백, 글자 크기 | `index.html` |
| 테마 색상(배경, 강조색, 버튼 글씨, 테두리) | `style.css` (학교별 `body.theme-…`) |
| 헤더 책 로고 색 | `style.css` (`--logo-…`) |
| 시작 화면(스플래시) 색 | `style.css` (`--sp-…`) |
| 시작 화면 보이는 시간 (지금 2.3초) | `main.js` |
| 테마 이름, 테마 선택 버튼 모양·순서 | `index.html` (설정 화면 부분) |
| 단어 추가 · 뜻 수정 · 오타 수정 | `words.js` |
| 품사 그룹 구성(어떤 품사가 어느 그룹에 속하는지) | `app.js` (`POS_GROUPS`) |
| 품사 설명 카드 문구 | `pos-guide.js` (`POS_GUIDE_DATA`) |
| 카테고리 카드의 표시 방식, "준비 중" 안내 | `category.js` |
| Stage 목록, 진도율, 잠금 규칙 | `days.js` |
| 단어 학습 카드/목록 동작 | `study.js` |
| 퀴즈 진행, 스펠링 채점 규칙, 영→한 뜻 입력 | `quiz.js` |
| 복습 게임의 보기 고르는 규칙 (오답 후보, 개수) | `quiz.js` (`buildChoices`) |
| 정답 후 넘어가는 시간 (지금 3초, 한영 테스트·복습 게임 공통) | `quiz.js` (`CORRECT_NEXT_DELAY`) |
| 클리어한 Stage의 복습 버튼 2개 표시 조건 | `study.js` (`openStudyView`) |
| 결과 화면 문구, 클리어 기록 방식 | `result.js` |
| 오답노트 동작 | `notebook.js` |
| 챌린지 화면 문구·배치 | `index.html` (`view-challenge`, `view-puzzle`) |
| 챌린지 규칙 (칸 채우는 조건, 보너스 날짜, 버튼 문구) | `challenge.js` |
| 챌린지 화면 퍼즐 크기 | `challenge.js` (`PUZZLE_MAIN_MAX_HEIGHT`) |
| 달마다 퍼즐 그림 넣기 | 그림 파일만 올리기 (코드 수정 불필요, 10번 항목) |
| 설정 항목 동작, 백업/복원 | `settings.js` |
| 클라우드 자동 저장, 구글 로그인, "어느 진도를 쓸까요?" 창 | `sync.js` |
| 클라우드를 쓸 수 있는 가족 이메일 | Firebase 관리 화면 → Firestore → 규칙 (코드 수정 없음) |
| 발음(TTS) 동작, 화면 전환, 헤더 제목 | `app.js` |

> 자바스크립트 파일(`.js`)이나 `style.css`를 고치면 **`index.html`의 버전 번호도 함께 올려야** 합니다. (3번 참고)
> 그래서 대부분의 수정은 "고친 파일 + `index.html`" 두 개를 업로드하게 됩니다.

## 3. 버전 번호 올리는 법 (중요)

아이폰과 브라우저는 한 번 받은 파일을 저장해 두고 재사용합니다. 파일을 고쳐 올려도 **옛 파일이 계속 보이는** 일이 생기는 이유입니다. 파일 주소 끝의 `?v=숫자`를 바꾸면 브라우저가 새 파일로 인식합니다.

**예: `quiz.js`를 고쳤을 때**

1. `index.html`을 열고 맨 아래쪽에서 아래 줄을 찾습니다.
   ```html
   <script src="./quiz.js?v=1"></script>
   ```
2. 숫자를 1 올립니다.
   ```html
   <script src="./quiz.js?v=2"></script>
   ```
3. `quiz.js`와 `index.html`을 함께 업로드합니다.

- `style.css`를 고쳤다면 `index.html` 위쪽의 `./style.css?v=1` 줄을 바꿉니다.
- 고친 파일의 번호만 올리면 됩니다. 다른 파일 번호는 그대로 둡니다.
- **한 번 쓴 번호는 다시 쓰지 마세요.** 같은 번호면 아이폰이 예전에 받아 둔 다른 내용의 파일을 계속 쓸 수 있습니다. (그래서 `app.js`와 `challenge.js`는 `?v=10`부터 다시 셉니다)
- `index.html`만 고쳤다면 번호를 올릴 필요가 없습니다.

## 4. GitHub에 올릴 때 주의점

**업로드 방법 (웹 브라우저)**
저장소 페이지 → **Add file** → **Upload files** → 파일들을 끌어다 놓기 → 아래 **Commit changes**.

- **파일만 끌어다 놓으세요.** 폴더째 올리면 하위 폴더가 생겨 화면이 깨집니다.
- **같은 이름의 파일은 자동으로 덮어쓰기** 됩니다. 처음 분리 버전을 올릴 때는 기존 `index.html`이 새 것으로 바뀝니다.
- **파일 이름의 대소문자를 바꾸지 마세요.** GitHub Pages는 `App.js`와 `app.js`를 다른 파일로 봅니다.
- **`apple-touch-icon.png`와 `volleyball.png`는 지우지 마세요.**
- 커밋 메시지는 무엇을 바꿨는지 짧게 적어 두면 나중에 되돌리기 쉽습니다. 예: `퀴즈 결과 문구 수정`

**올린 뒤 확인**
- 반영까지 보통 1~10분 걸립니다. 저장소의 **Actions** 탭에서 초록색 체크가 뜨면 배포 완료입니다.
- 아이폰 홈 화면 앱은 **앱 전환 화면에서 위로 밀어 완전히 종료한 뒤** 다시 실행해야 새 버전이 보이는 경우가 많습니다.

**되돌리기**
저장소에서 파일을 열고 **History**를 누르면 예전 버전을 볼 수 있습니다. 문제가 생기면 예전 내용을 복사해 다시 올리면 됩니다.

## 5. 절대 바꾸면 안 되는 것

| 항목 | 이유 |
|---|---|
| `app.js`의 `STORAGE_KEY = "AIN_ENG_APP_V2"` | 바꾸면 기존 진도·오답노트·설정을 읽지 못합니다 |
| `app.js`의 `state` 항목 이름(`clearedDays`, `notebook` 등) | 같은 이유 |
| `index.html` 맨 아래 스크립트 순서 (`words` → `app` → 화면들 → `main`) | 순서가 바뀌면 앱이 시작되지 않습니다 |
| `index.html`의 `id="..."` 이름 | JS 파일들이 이 이름으로 버튼과 글자를 찾습니다 |
| 파일 이름 | 바꿔야 한다면 `index.html`의 연결 줄도 똑같이 바꿔야 합니다 |

## 6. 단어 데이터 (`words.js`)

한 줄에 한 단어이며 형식은 아래와 같습니다.

```
영단어|한글 뜻|품사|레벨|발음기호
afraid|두려워하는, 걱정하는|adj|A1|
```

- 칸 구분은 세로 막대 `|` 입니다. 뜻 안에는 `|`를 쓰지 마세요.
- 레벨은 `A1`, `A2`, `B1`, `B2`, `C1` 중 하나입니다. 어떤 레벨에 단어가 생기면 그 레벨 탭이 자동으로 열립니다.
- 품사 표기는 `n`, `v`, `adj`, `adv`, `pron`, `prep`, `det`, `num`(서수 포함), `conj`, `exclam`, `modal v`, `aux. v`, `def. art.`, `indef. art.`, `INF` 중 하나를 씁니다.
- 파일 맨 아래 `` ` `` 기호(백틱)는 지우지 마세요.
- **주의:** 어떤 품사 그룹에 단어를 추가·삭제하면 그 그룹의 Stage 구성이 다시 섞여, 이미 쌓인 진도가 다른 단어를 가리키게 됩니다. 실사용 중이라면 단어 변경 후 설정의 초기화를 안내하세요.

모든 파일을 한 폴더에 내려받은 뒤 `index.html`을 더블클릭하면 브라우저에서 열립니다(인터넷 연결 필요).

- 내 컴퓨터에서 연 앱과 GitHub Pages 앱은 **진도 저장 공간이 서로 다릅니다.** 여기서 테스트한 진도는 실제 앱에 영향을 주지 않습니다.
- 아이폰의 Safari 탭과 홈 화면 앱도 저장 공간이 서로 다릅니다.

## 9. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 화면이 하얗거나 버튼이 반응 없음 | 파일이 모두 업로드됐는지, 이름의 대소문자가 맞는지, 하위 폴더에 들어가지 않았는지 |
| 고쳤는데 옛 화면이 보임 | `?v=` 번호를 올렸는지, 홈 화면 앱을 완전히 종료 후 다시 열었는지, 배포가 끝났는지(Actions 탭) |
| 진도가 사라짐 | Safari 탭이 아니라 홈 화면 앱에서 열었는지, 설정에서 초기화를 누르지 않았는지 |
| 홈 화면 앱이 열리지 않음(404) | 저장소 이름을 바꾸면 주소가 바뀌므로, 새 주소에서 홈 화면에 다시 추가해야 합니다 |
| 디자인이 전부 깨짐 | 인터넷 연결 확인 (디자인 라이브러리 Tailwind를 인터넷에서 받아옴) |

## 10. 데일리 챌린지 퍼즐 그림 넣기

**코드는 고치지 않고 그림 파일만 올리면 됩니다.** `index.html`의 버전 번호도 올릴 필요가 없습니다.

| 항목 | 규칙 |
|---|---|
| 파일 이름 | `puzzle-연도-월.확장자` — 월은 두 자리 (예: `puzzle-2026-11.jpg`, `puzzle-2027-01.jpg`) |
| 확장자 | `jpg`, `jpeg`, `png`, `webp` 중 하나, **소문자만** (`.JPG`는 못 찾음) |
| 위치 | 저장소 맨 위(다른 파일들과 같은 곳) |
| 비율 | 7:5에 가까울수록 좋음 (판이 그림 비율 그대로 만들어지므로 달라도 잘리지 않음) |
| 크기 | 가로 1400픽셀 안팎 |
| 용량 | 300KB 안팎 (500KB 이하). 크면 챌린지 화면이 늦게 뜸 |

- 한 달에 한 파일만 올립니다. 같은 달에 `jpg`와 `png`가 둘 다 있으면 `jpg`를 씁니다.
- 그 달 그림이 없으면 기본 풍경 그림이 나옵니다. 퍼즐 동작은 똑같습니다.
- 챌린지를 처음 시작한 달에는 한 번만, 그때까지 영→한·한→영을 모두 끝낸 Day 수만큼 1일부터 지난 칸이 채워집니다 (`challenge.js`의 `runChallengeCatchUp`).
- 지난달 그림은 지우지 마세요. 지난달 퍼즐을 넘겨 볼 때 필요합니다.
- 이미 올린 달의 그림을 **다른 그림으로 바꾸면** 아이폰이 옛 그림을 기억할 수 있습니다. 앱을 완전히 종료 후 다시 열어도 안 바뀌면 문의하세요.

| 1. 카라스노 | `theme-dark` | 다크 (기기 다크모드 자동 연동 시 이 테마) |
| 2. 네코마 | `theme-ios` | 밝음 · 레드 |
| 3. 아오바조사이 | `theme-playful` | 밝음 · 청록 |

- 코드 안의 이름은 예전 테마 이름 그대로입니다. 바꾸면 저장된 테마 설정을 읽지 못하니 바꾸지 마세요.
- 화면에는 **Stage**라고 보이지만, 코드와 저장 데이터 안에서는 예전 이름 **day**를 그대로 씁니다 (같은 이유).
- 홈 화면 아이콘을 바꾼 뒤 새 아이콘이 안 보이면, 홈 화면 앱을 지우고 다시 추가해야 할 수 있습니다. **그 전에 반드시 설정 → 진도 백업을 해 두세요.**

## 12. 클라우드 자동 저장 (구글 로그인)

설정 → **진도 저장 → 자동 저장 (클라우드)** 에서 구글로 로그인하면, 진도가 바뀔 때마다 몇 초 뒤 Firebase(구글)에 자동으로 저장됩니다. 폰을 바꾸거나 홈 화면 앱을 다시 추가해도 로그인하면 진도가 돌아옵니다.

- 폰에도 예전처럼 저장하므로 로그인하지 않아도, 인터넷이 끊겨도 앱은 그대로 동작합니다.
- 다른 기기(아이패드, PC)에서 같은 계정으로 로그인해도 됩니다. 앱을 열거나 다시 화면으로 돌아올 때마다 클라우드를 확인해서, 그사이 다른 기기에서 공부했으면 최근 진도로 바뀝니다 (화면이 한 번 새로 고침됨). 두 기기에서 **동시에** 쓰면 나중에 저장한 쪽이 남습니다.
- 앱을 열 때 폰과 클라우드의 진도가 서로 다르면 **"어느 진도를 쓸까요?"** 창이 뜹니다. 고르지 않은 쪽은 덮어써집니다.
- 쓸 수 있는 계정은 Firebase 관리 화면 → Firestore → **규칙**의 이메일 목록으로 정합니다. 가족이 늘면 목록에 이메일을 추가하고 "게시"를 누르세요.
- Firebase 프로젝트: `ain-word` / 승인된 도메인: `papajinin.github.io`
- 설정의 **초기화**를 누르면 클라우드의 진도도 같이 초기화됩니다. 텍스트 백업은 그대로 쓸 수 있으니 중요한 순간에는 함께 해 두세요.
- 처음 로그인하기 전에는 **텍스트 백업을 먼저** 해 두세요.
